Backend ownership during NestJS migration

Active API: lume-nestjs/ (NestJS; REST /api/v2 and GraphQL /api/v2/graphql).
Run `pnpm --filter lume-backend setup` once to install its npm-locked dependencies.
The backend workspace package is a task gateway: dev/start/build/test/typecheck/
lint and db:migrate:sql delegate to lume-nestjs. Existing root dev:admin commands
therefore launch NestJS. Runtime and database configuration is read by NestJS.
Lint is read-only; lint:fix is the explicit modifying command.

Legacy Express code: src/, prisma/, drizzle/, tests/ and their old dependencies
remain solely for migration comparison and rollback. Their package commands are
explicitly named legacy:<command>. Do not use legacy database setup/refresh commands
on the active database. Removal is tracked in docs/nestjs-migration-tasks.txt.

Frontend UI: packages/@lume/module-ui/src/modules/<feature>/static (repository root).
The legacy src/modules/*/static paths are compatibility symlinks, not copies.
Both active frontends compile from the package directly.

The final API path will be backend/api after deployment paths and rollback are
prepared. The running service still points to backend/lume-nestjs; moving it early
would break service restart. This document describes the transition, not completion.
