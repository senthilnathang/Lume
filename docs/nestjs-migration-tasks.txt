NestJS migration and backend cleanup — execution tracker
Started: 2026-10-23
Status: IN PROGRESS. This file supersedes historical completion claims and plans.

Objective
Complete the standalone Express application's migration to NestJS, preserve
required behavior and data, remove legacy runtime dependencies, and leave a
documented backend layout with reproducible tests and deployment commands.
External integrations remain disabled. Existing uncommitted work is preserved.
NestJS's @nestjs/platform-express HTTP adapter is not the legacy application.

Target ownership and folder structure
  backend/api/                 NestJS application (move at final deployment cutover)
    src/core/                  shared infrastructure and cross-cutting services
    src/modules/<feature>/     module, controllers, DTOs, services, persistence
    src/graphql/               GraphQL transport adapters
    prisma/                    canonical Prisma schema and generation
    migrations/                ordered SQL migrations and runner
    test/{unit,integration}/   backend regression tests
    scripts/                   backend maintenance and verification
    deploy/                    deployment templates
  packages/@lume/module-ui/    shared frontend modules; no backend runtime code
  apps/web-lume/               Vue administration client
  apps/riagri-website/         Nuxt public website
  docs/                       architecture, migration evidence and operations

The running service currently uses backend/lume-nestjs. Keep this location until
deployment references and rollback are prepared. Legacy source is retained until
required behavior, scaffolding and data-import paths have replacements.
